Research date: 2026-09-22. Licence/activity data for GitHub repos below was read from the
GitHub REST API (`/repos/{owner}/{name}`: `license.spdx_id`, `pushed_at`, `stargazers_count`)

## Which open-source JSX/ExtendScript script collections for Illustrator exist?

### Takeaway
The large, genuinely reusable collections are MIT-licensed: Sergey Osokin (creold, ~1.1k stars, actively maintained into Aug 2026), Alexander Ladygin (~1.5k stars, last pushed 2023), and Hiroyuki Sato / shspage (472 stars, but dormant since 2018). The two big traps are John Wundes' js4ai, which has **no GitHub licence** and is actually under a **4-clause BSD with an advertising clause** (not MIT, and GPL-incompatible), and Vasily Hall's Silly-V/Adobe-Illustrator (472 stars) which has **no licence at all** — all-rights-reserved by default.

### Cited Findings
- **creold/illustrator-scripts (Sergey Osokin)** — licence `MIT` (GitHub API `spdx_id: MIT`), 1,114 stars, last push 2026-08-21, so it is currently maintained. README organises scripts by: Artboard (9), Color (15), Draw (6), Export (2), Group|Mask (7), Item (15), Layer (3), Path (7), Select (9), Style (8), Text (7), Utility (6), View (1). Representative scripts: ArtboardsFinder, ConvertToGradient, DrawPolyline, ExtUngroup, RenameItems, SelectBySwatches, StrokesWeightUp, MakeNumbersSequence. - Per-category README docs exist, e.g. the View category doc — [md/View.md](https://github.com/creold/illustrator-scripts/blob/master/md/View.md)
- **alexander-ladygin/illustrator-scripts** — licence `MIT` (API), 1,505 stars (largest of the collections), 375 forks, last push 2023-09-04. README states "All scripts is licensed under the MIT licence." ~30+ JSX scripts: artboard management (resize, rotate, create from selection), object manipulation (harmonizer, randomizer, replacer, duplicator), clipping/masking (puzzle clipper, cropulka), text and colour tools (batch text edit, transfer swatches), utilities (SVG importer, compound fix, grid generator) — [alexander-ladygin/illustrator-scripts](https://github.com/alexander-ladygin/illustrator-scripts)

### Inferences
- For a shipped derived product, the safe borrow pool is: creold (MIT, current), Ladygin (MIT, 2023), shspage (MIT, frozen). All three permit closed-source redistribution with attribution + licence text retained.
- js4ai is usable but the advertising clause (clause 3) is an ongoing obligation in marketing materials — most teams treat 4-clause BSD as "avoid unless you really want that script". It is also GPL-incompatible.
- No licence at all (Silly-V, iconifyit, several MCP servers below) means default copyright: reading for ideas is fine, copying code is not. An email asking the author to add a licence is the cheap fix.
- Because shspage has not been touched since 2018, its scripts predate modern Illustrator artboard/appearance APIs; expect to re-test anything borrowed from there.

### Gaps
- Astute Graphics' exact free-script licence text could not be retrieved; their docs site did not expose a script-level EULA in search results. Treat as proprietary until confirmed.
- I found no canonical repo literally named "ai-scripts"; the closest large curated sets are the four named above. If a specific "ai-scripts" repo is meant, it was not surfaced by GitHub search.
- Mark Bean (m1b), a well-known Illustrator/InDesign scripter, does not have an `m1b/Illustrator-Scripts` repo under that exact name (API returned Not Found); his work may live under a different repo name not confirmed here.

## Which MCP servers for Adobe Illustrator exist besides adb-mcp?

### Takeaway
The standout is **ie3jp/illustrator-mcp-server** (MIT, npm `illustrator-mcp-server` v1.8.0, 67 tools, pushed 2026-09-14) — by far the most complete and the most directly reusable tool taxonomy. Adobe itself now ships a built-in MCP server in Illustrator **Beta 30.4+ only** (~40 tools, read/analyse/export oriented). Most other community servers are thin "run arbitrary ExtendScript" wrappers, and several of the popular ones carry **no licence**.

### Cited Findings
- **ie3jp/illustrator-mcp-server** — `MIT` (API), 127 stars, last push 2026-09-14, 204 commits. Published to npm as `illustrator-mcp-server`, latest 1.8.0 (2026-09-14), `license: MIT`, requires Node 20+; installable via `npx illustrator-mcp-server` or a one-click `.mcpb`. Transport: local stdio process launched by the MCP client. Talks to Illustrator by generating **ExtendScript/JSX** driven through **AppleScript on macOS** and **PowerShell COM automation on Windows** (README notes Windows "not yet tested on real hardware"). Supported: Illustrator 2024+ verified, 2020+ unverified — [ie3jp/illustrator-mcp-server](https://github.com/ie3jp/illustrator-mcp-server), [npm](https://libraries.io/npm/illustrator-mcp-server)
- ie3jp tool list (67 total) — **Read (21):** get_document_info, get_artboards, get_layers, get_document_structure, list_text_frames, get_text_frame_detail, get_colors, get_path_items, get_groups, get_effects, get_images, get_symbols, get_guidelines, get_overprint_info, get_separation_info, get_selection, find_objects, check_contrast (WCAG), extract_design_tokens (CSS vars / JSON / Tailwind), list_fonts, convert_coordinate. **Modify (39):** create_rectangle, create_ellipse, create_line, create_text_frame, create_path (with Bezier handles), place_image, import_svg_as_editable, modify_object, convert_to_outlines, assign_color_profile, create_document, close_document, resize_for_variation, align_objects, replace_color, manage_layers, place_color_chips, save_document, open_document, group_objects, ungroup_objects, duplicate_objects, set_z_order, move_to_layer, delete_objects, manage_artboards, manage_swatches, manage_linked_images, manage_datasets (variables/datasets import/export), apply_graphic_style, list_graphic_styles, apply_text_style, list_text_styles, create_gradient, create_path_text, place_symbol, select_objects, create_crop_marks, place_style_guide, undo. **Export (2):** export (SVG/PNG/JPG by artboard/selection/UUID), export_pdf (crop marks, bleed, downsampling, output intent). **Utility (3):** preflight_check, check_text_consistency, set_workflow — [README](https://github.com/ie3jp/illustrator-mcp-server)
- ie3jp documents a **UUID-based object handle** model and a coordinate-system switch: CMYK/print documents use `document` coordinates (origin bottom-left, Y up) while RGB/web use `artboard-web` (origin top-left of artboard, Y down), with `set_workflow` to override auto-detection — [README](https://github.com/ie3jp/illustrator-mcp-server)
- ie3jp's own stated limitations, useful as a map of ExtendScript's hard edges: live-effect parameters can be detected but not read; colour-profile **assignment** only, no conversion; **bleed settings cannot be read (Illustrator API limitation)**; no WebP export; font embedding mode not controllable except via PDF presets — [README](https://github.com/ie3jp/illustrator-mcp-server)
- `pattanakim/illustrator-mcp-server` and `gyuminlee-repo/illustrator-mcp-server` appear in search with identical descriptions — they are **forks/mirrors of ie3jp**, not separate projects — [pattanakim](https://github.com/pattanakim/illustrator-mcp-server), [gyuminlee-repo](https://github.com/gyuminlee-repo/illustrator-mcp-server)
- **Adobe's official built-in MCP server** — ships inside **Illustrator (Beta) 30.4+ only** and is still beta-only as of August 2026. You obtain an auth key + URL from the app's settings and connect via `mcp-remote` (i.e. a local HTTP/SSE-style remote endpoint proxied to stdio), not a stdio binary. ~40 tools/actions, focused on analysing and batch-processing **existing** documents: analysis, bulk recolouring, variations, batch artboard export, font and broken-link checks. It reportedly cannot create new objects, text frames or documents, and is export-only (no save) — [Adobe helpx: MCP server in Illustrator](https://helpx.adobe.com/in/illustrator/desktop/connect-with-other-apps-and-tools/about-using-ai-tools-with-illustrator.html) (page returned 403 to automated fetch; details taken from search summary and ie3jp's comparison table — verify before relying on the exact tool count)
- **mikechambers/adb-mcp** — `MIT` (API), 711 stars, last push 2026-07-08, 214 commits. Architecture: `AI ↔ MCP Server ↔ Command Proxy Server (Node.js, Socket.IO/WebSocket) ↔ Plugin ↔ Adobe App`. Photoshop (26.0+), Premiere Pro (25.3+) and InDesign use **UXP** plugins; **Illustrator and After Effects use CEP/ExtendScript** because they lack UXP support. The Illustrator server (`ai-mcp.py`) exposes document operations plus an **arbitrary-ExtendScript execution** tool rather than a large typed tool set — [mikechambers/adb-mcp](https://github.com/mikechambers/adb-mcp), [UXP Plugins overview](https://deepwiki.com/mikechambers/adb-mcp/6-uxp-plugins), [author's blog post](https://www.mikechambers.com/blog/post/2025-06-06-exploring-ai-integration-with-adobe-photoshop-indesign-and-premiere-pro/)
- **spencerhhubert/illustrator-mcp-server** — **no licence file** (API returned no `license`), 57 stars, last push 2024-12-16, only 6 commits. macOS-only; drives Illustrator via **AppleScript** and simply "send[s] scripts straight to Illustrator and look[s] at the result" — a single arbitrary-JSX tool plus a screenshot back. Run locally with `uv`, not published to PyPI. A third-party scanner rates it poorly on safety precisely because it executes arbitrary scripts — [spencerhhubert/illustrator-mcp-server](https://github.com/spencerhhubert/illustrator-mcp-server), [agentseal score](https://agentseal.org/mcp/https-githubcom-spencerhhubert-illustrator-mcp-server)
- **krVatsal/illustrator-mcp** — **no licence** per API, 153 stars (the most popular unlicensed one), last push 2026-07-04. Cross-platform: Windows via COM automation, macOS via AppleScript/osascript; sends ExtendScript commands from a local MCP server so agents can create vector graphics from natural language — [krVatsal/illustrator-mcp](https://github.com/krVatsal/illustrator-mcp), [listing](https://mcprepository.com/krVatsal/illustrator-mcp), [LobeHub listing](https://lobehub.com/mcp/krvatsal-illustrator-mcp-server)
- **jinkeda/Illustrator_MCP** — `MIT`, 7 stars, last push 2026-09-17 (active). Offers "ExtendScript via a single powerful tool, or … purpose-built tools for document I/O, state inspection, and structured queries" — [jinkeda/Illustrator_MCP](https://github.com/jinkeda/Illustrator_MCP)
- **Elguajo/Illustrator_MCP** — `MIT`, 0 stars, last push 2026-09-09. A fork of jinkeda's that "adds bridge authentication, CI, and hardening work" — [Elguajo/Illustrator_MCP](https://github.com/Elguajo/Illustrator_MCP)
- **slashprint/illustrator-mcp** — no licence, 3 stars, last push 2026-04-29 — [slashprint/illustrator-mcp](https://github.com/slashprint/illustrator-mcp)
- **scort1213/illustrator-mcp** — no licence, 0 stars, last push 2026-09-17 — [scort1213/illustrator-mcp](https://github.com/scort1213/illustrator-mcp)
- adb-mcp is indexed in the usual MCP directories as "Adobe Creative Suite MCP Server" — [PulseMCP](https://www.pulsemcp.com/servers/mikechambers-adobe-creative-suite), [playbooks.com](https://playbooks.com/mcp/mikechambers/adb-mcp); ie3jp's server is indexed at [mcp.so](https://mcp.so/servers/illustrator-mcp-server) and [MCPdb](https://mcpdb.org/mcps/illustrator-mcp-server)

### Inferences
- There is a clean split in design philosophy: **one-tool servers** (spencerhhubert, krVatsal, adb-mcp's Illustrator side) that hand the model raw ExtendScript, versus **typed-tool servers** (ie3jp, Adobe official) that expose 40–67 named operations. The typed approach is what is worth copying; ie3jp's tool table is effectively a ready-made spec.
- ie3jp is the only Illustrator MCP server that is simultaneously MIT, actively maintained in 2026, published to npm, and broad in coverage. It is the single highest-value reuse target.
- Because Illustrator has no UXP, every server in this space converges on the same transport: ExtendScript text injected via AppleScript (`do javascript`) on macOS or COM on Windows, or a CEP extension bridge. Any new project will land on the same mechanism.
- The `undo`/`force_unlock` and UUID-handle patterns in ie3jp suggest the practical pain points: object identity across calls and locked/hidden objects. Worth designing for from day one.

### Gaps
- Adobe's own helpx page returned HTTP 403 to automated fetching (twice, on both `/in/` and US paths), so the official tool count (~40) and the "cannot create objects" claim rest on a search-engine summary plus ie3jp's comparison table — a competitor's characterisation. Verify manually in a browser.
- No PyPI-published Illustrator MCP package was found; the Python servers (spencerhhubert, jinkeda/Elguajo) are run from source with `uv`.
- Licence for krVatsal (153 stars) is genuinely absent, not merely undetected by the API — no LICENSE in the repo root was reported.

## What are the most commonly automated Illustrator operations, and how hard is each in ExtendScript?

### Takeaway
Ranking by how often they recur across creold/Ladygin/js4ai and across the MCP tool sets: artboards, export, selection/find, colour and swatch replacement, text/typography, layers, alignment/distribution, then placed images/links, symbols, and data-merge variables. The DOM covers nearly all of it; the notable holes are **Pathfinder** (no DOM API at all) and live-effect parameters, which require `app.executeMenuCommand` or an Action played via `app.doScript`.

### Cited Findings
- **Pathfinder has no DOM counterpart.** Community consensus: "There is no counterpart to the pathfinder panel in ExtendScript"; the workarounds are menu commands for the Pathfinder *effects* — `app.executeMenuCommand("Live Pathfinder Add")`, `"Live Pathfinder Intersect"`, `"Live Pathfinder Exclude"` — applied to selected, grouped paths, followed by `app.executeMenuCommand("expandStyle")` to flatten the live effect into real paths — [Adobe forum: Shape Mode scripting, Unite equivalent](https://community.adobe.com/t5/illustrator-discussions/shape-mode-scripting-continued-unite-equivalent-script/td-p/11367813), [Adobe forum: JavaScript commands for pathfinder](https://community.adobe.com/t5/illustrator-discussions/looking-for-javascript-commands-for-path-finder-operation/m-p/12356249)
- **Actions can be played from script** since Illustrator CS6 with `app.doScript("Action", "Set")`, which is the escape hatch for anything with no DOM API — [Adobe forum: dynamic action with app.doScript](https://community.adobe.com/t5/illustrator/creating-a-dynamic-action-to-use-with-app-doscript-method/m-p/8918373), [Adobe forum: calling an action in ExtendScript](https://community.adobe.com/t5/illustrator-discussions/calling-an-action-in-extendscript-toolkit/td-p/3626308)
- **Known deadlock:** "When you make an Action that runs a script that uses `app.doScript()`, Illustrator can freeze, as Illustrator Actions and scripts run in different execution threads" — nesting an action inside a script that was itself launched from an action is unsafe — [Adobe forum](https://community.adobe.com/t5/illustrator-discussions/running-script-from-actions/td-p/7223168)
- **Artboards** dominate every collection: creold has a 9-script Artboard category (incl. ArtboardsFinder); Ladygin covers artboard resize, rotate, and create-from-selection; ie3jp exposes `get_artboards`, `manage_artboards` (add/remove/resize/rename/rearrange), `resize_for_variation`, and `export` with an `artboard:all` batch mode — [creold](https://github.com/creold/illustrator-scripts), [ladygin](https://github.com/alexander-ladygin/illustrator-scripts), [ie3jp](https://github.com/ie3jp/illustrator-mcp-server)
- **Colour/swatches/recolouring** is the second-largest cluster: creold's Color category is its biggest at 15 scripts (ConvertToGradient, SelectBySwatches); js4ai has AddSwatchesLightAndShadow, CMYKtoPMS, vary_hues; Ladygin has transfer-swatches and a colour harmonizer; ie3jp has `get_colors`, `replace_color` (with tolerance), `manage_swatches`, `create_gradient`, `place_color_chips`, `extract_design_tokens`. Adobe's own beta MCP lists "bulk recoloring" as a headline workflow — [creold](https://github.com/creold/illustrator-scripts), [js4ai](https://github.com/johnwun/js4ai), [ie3jp](https://github.com/ie3jp/illustrator-mcp-server)
- **Selection/find** recurs everywhere: creold Select (9 scripts), js4ai SelectPathsBySize / selectTextBySize / groupOverlappingObjects, ie3jp `find_objects` (by name, type, colour, font) and `select_objects` — [creold](https://github.com/creold/illustrator-scripts), [js4ai](https://github.com/johnwun/js4ai)
- **Text/typography:** creold Text (7), js4ai divideTextFrame / joinTextFrames / textTweaker, shspage batchTextEdit, Ladygin batch text edit; ie3jp `list_text_frames`, `get_text_frame_detail` (kerning, paragraph settings), `create_text_frame` (point or area), `create_path_text`, `apply_text_style`, `convert_to_outlines`, `check_text_consistency` — [creold](https://github.com/creold/illustrator-scripts), [shspage](https://github.com/shspage/illustrator-scripts), [ie3jp](https://github.com/ie3jp/illustrator-mcp-server)
- **Groups/masks:** creold Group|Mask (7 incl. ExtUngroup), Ladygin puzzle clipper and cropulka, ie3jp `group_objects` (supports clipping masks), `ungroup_objects`, `get_groups` (groups, clipping masks, compound paths) — [creold](https://github.com/creold/illustrator-scripts), [ladygin](https://github.com/alexander-ladygin/illustrator-scripts)
- **Placed images / linking:** ie3jp `get_images` (resolution, broken-link detection, colour-space mismatch, scale factor), `place_image` (linked or embedded, **SVG rejected**), `manage_linked_images` (relink/embed), `import_svg_as_editable`. Adobe's beta MCP also headlines "font / broken-link checks" — [ie3jp](https://github.com/ie3jp/illustrator-mcp-server)
- **Data merge / variables:** ie3jp `manage_datasets` — list/apply/create datasets, import/export variables. This is the only server found that exposes Illustrator's variables/datasets — [ie3jp](https://github.com/ie3jp/illustrator-mcp-server)
- **Symbols:** ie3jp `get_symbols` (definitions and instances) and `place_symbol` (place or replace) — [ie3jp](https://github.com/ie3jp/illustrator-mcp-server)
- **Export:** creold has only a 2-script Export category, but ie3jp's `export` (SVG/PNG/JPG by artboard, selection, or UUID) and `export_pdf` (crop marks, bleed, selective downsampling, output intent) plus `create_crop_marks` and `preflight_check` show where the real demand sits — [ie3jp](https://github.com/ie3jp/illustrator-mcp-server)
- Scripts are commonly installed/invoked by drag-and-drop or via the Scripts menu, and users routinely bind them to Actions for keyboard shortcuts — [Running scripts via drag-and-drop](https://aiscripts.medium.com/running-scripts-via-drag-and-drop-84021c505ed4), [Adobe forum: shortcut without an action](https://community.adobe.com/t5/illustrator-discussions/v28-7-9-macos-setting-a-shortcut-for-illistrator-scripts-without-the-need-of-an-action/td-p/15566841), [designer write-up on adding scripts](https://danflint.me/2023/10/18/adding-useful-scripts-to-adobe-illustrator/)

### Inferences
Prioritised list of operations to wrap as tools, with a difficulty read. Difficulty ratings are my inference from the DOM coverage evidenced above, not a cited claim.

1. **Artboards** (add/remove/resize/rename/rearrange, fit-to-selection, batch export per artboard) — Easy. Full DOM: `document.artboards`, `artboardRect`. Highest frequency across every source.
2. **Export / save-for-web** (PNG/JPG/SVG per artboard or selection, PDF with marks and bleed) — Easy to Medium. `exportFile` + `ExportOptionsPNG24/SVG/JPEG`, `saveAs` + `PDFSaveOptions`. Medium because option objects are large and print options (bleed) are partly unreadable.
3. **Selection / find by criteria** (type, name, colour, font, size, layer) — Easy. Iterate `pageItems`, set `document.selection`. Needs a stable object-handle scheme (ie3jp uses UUIDs).
4. **Colour, swatches and recolouring** (find/replace colour with tolerance, CMYK↔RGB↔spot, swatch library apply, gradient creation, token extraction) — Easy to Medium. DOM colour objects are straightforward; global/spot swatch handling and "Recolor Artwork" itself are not scriptable, so global-swatch substitution is the practical route.
5. **Text and typography** (bulk edit, find/replace, style application, area vs point type, text-on-path, outline conversion) — Medium. `TextFrame`/`TextRange`/`characterAttributes` are complete but verbose; font resolution by name is a common failure point.
6. **Layers** (create, rename, reorder, show/hide, lock/unlock, move items between layers, flatten) — Easy. `document.layers`, `item.move()`.
7. **Alignment and distribution** — Easy but manual. No DOM align API; you compute from `geometricBounds`/`visibleBounds` and set `position`. Deciding geometric vs visible bounds (strokes, effects) is the real work.
8. **Transform / duplicate / z-order** (translate, scale, rotate, step-and-repeat, bring-to-front) — Easy. `translate()`, `resize()`, `rotate()`, `duplicate()`, `zOrder()`.
9. **Groups, clipping masks, compound paths** — Medium. Creating a clipping mask requires building a `GroupItem`, setting `clipped = true` and ordering the mask path on top; release/expand often falls back to menu commands.
10. **Placed images and links** (place linked/embedded, relink, detect broken links, report effective PPI) — Medium. `PlacedItem`/`RasterItem` expose `file`, `matrix`; effective resolution must be derived from the matrix scale.
11. **Pathfinder / shape modes (unite, minus front, intersect, exclude, divide, trim, merge, crop, outline)** — **Hard; no DOM API.** Requires `app.executeMenuCommand("Live Pathfinder Add"|"Live Pathfinder Intersect"|…)` followed by `expandStyle`, or a pre-recorded Action played with `app.doScript("Action","Set")`. Flag: menu-command names are locale-sensitive in some Illustrator builds, and the Action route means shipping an `.aia` action set the user must load.
12. **Path geometry editing** (offset path, simplify, flatten curves, join, average, add/remove anchors, outline stroke) — Medium to Hard. Anchor/handle maths via `pathPoints` is doable (shspage's flatten/handleGlue are exactly this), but Offset Path, Simplify and Outline Stroke are **effects/menu commands**, not DOM — same Action/menu-command caveat as Pathfinder.
13. **Symbols** (list definitions, place/replace instances, break link) — Medium. `document.symbols`, `symbolItems`.
14. **Graphic styles, character/paragraph styles** (list and apply) — Medium. Styles are addressable and applicable but not creatable with arbitrary appearance from script.
15. **Data merge / variables and datasets** (bind text and images to variables, apply datasets, import/export variable XML) — Medium to Hard. The DOM has `variables`/`dataSets` but the workflow is fiddly and poorly documented; ie3jp's `manage_datasets` is the only prior art found.
16. **Appearance and live effects** (drop shadow, blur, warp, 3D) — **Hard.** ie3jp states effect parameters "can be detected but not read". Applying effects means `applyEffect()` with a raw Live Effect XML string, or Actions/graphic styles.
17. **Prepress** (crop/trim marks, overprint, separations preview, colour-profile assignment, preflight) — Hard-ish and niche, but ie3jp proves it is achievable; note bleed settings cannot be read.

Rule of thumb for the architecture: everything in tiers 1–10 is honest DOM work; tiers 11, 12 and 16 need `executeMenuCommand` or `doScript` with an Action set, which means (a) shipping and installing an action set, (b) never nesting doScript inside a script launched by an action (documented freeze), and (c) handling locale-dependent menu-command strings.
